# 薬歴からの継続使用推定・相互作用チェック改善計画

- 作成日: 2026-09-15
- 状態: 調査・構想段階。判定ロジックの変更は未実施。
- 背景: COMによるカルテ追従の基本部分は実機確認済み。次の課題として、取り込んだ薬歴から現在使用中の薬を推定し、相互作用チェックに利用したい。
- 本書の位置付け: 現時点のコード調査結果と改善案の記録。スコア、猶予期間、薬剤マスターの具体的な値は未確定。

## 1. 目的

以下の薬を適切に区別し、現在使用している可能性のある薬の見逃しを減らす。

- 慢性疾患で長期に反復処方され、現在も使用している可能性がある薬。
- 急性疾患などで短期間だけ処方されたNSAIDs等。
- 頓用や間欠的に使用する薬。
- 数量が1、2などでも、実際には2週間・1か月以上使用する吸入薬等。
- 長期処方が途切れ、中断が疑われる薬。

処方・調剤履歴は実際の服薬を保証しない。特に「一時中断」「医師による中止」「自己中断」の理由は履歴だけでは確定できないため、推定と確認済み情報を区別する。

## 3. 確認できた問題点

### 3.1 スコアの入力が処方日の並びに偏っている

GetMedRanksAsyncはdidate、drugc、drugn、prisorgを取得する。数量・用法・回数をスコアに使用していないため、同じ日付の7日処方と90日処方を区別できない。

DBにはQua1、Times、Unit、UsageN、MeTrIdCl、Source、ReceiveDate、PrDate等が保存されている。UsageNには補足指示が結合される場合もある。まず保存情報を日数推定に利用できるか確認する。

### 3.2 月カバレッジは使用期間のカバレッジではない

現在は「処方があった月数 / 対象月数」であり、90日ごとの処方などが不利になる。開始したばかりの薬も、開始前の期間を含む分母によって低評価になりやすい。

ComputeMonthCvは処方がない月を含めていない。一方、月カバレッジは欠けた月を減点しており、2つの指標の意味を整理する必要がある。

### 3.3 慢性傾向と現在使用状態が混ざっている

最終処方日からの経過日数で直近性が低下するため、薬が残る長期処方でも継続判定が弱くなる。反対に、最近の短期処方が終了していても「最近」という理由で優先される。

履歴が少なく規則性が不明な場合も、現在は規則性の低さとして評価され、急性寄りになりやすい。

### 3.4 投与経路の一律補正が粗い

注射薬は慢性スコアを0.6倍するが、長期の定期注射にも適用される。吸入・外用・頓用等も、大まかな経路だけでは使用パターンを表せない。

### 3.5 製品変更で履歴が分断される

主に薬剤コード単位で集計するため、後発品や規格の変更で同一治療の継続性が途切れて見える。

### 3.6 訂正・重複データと抽出時の欠落

- ランク取得SQLには、薬歴表示側にあるRevisedの除外条件がない。
- 処方情報と調剤情報等が同じ処方を表す場合、日数や数量の二重計上を防ぐ必要がある。
- MakeLLMPromptは慢性・急性上位および閾値以上を集めるが、最終的に慢性優先で既定15剤に制限する。短期薬等が落ちる可能性がある。
- ランク取得時はコードなしの薬を名前で区別するが、ペイロード抽出時はDrugCで再集約するため、コードなしの複数薬が1つにまとめられる可能性がある。

### 3.7 プロンプトが誤判定を誘導する

サンプルの指示には以下がある。

- days_since_last >= 60なら「中断している」と出力。
- acuteが高い、またはdays_since_last <= 30なら「臨時処方」と出力。

90日処方の60日経過や、最近処方された慢性薬を誤分類し得る。サンプルコードだけでなく、実際に利用中のai_prompt_tplの保存済み指示も確認・改訂する。利用者が編集したテンプレートを無条件で上書きしない。

## 4. 改善設計案

### 4.1 判定を3軸に分ける

| 軸 | 候補値 |
|---|---|
| 治療パターン | 長期継続傾向、短期コース、頓用・間欠使用、不明 |
| 現在の使用状態 | 処方上は使用期間内、継続の可能性あり、終了推定、中断疑い、不明 |
| 根拠の確かさ | 日数明示、数量と用法から計算、過去の処方間隔から推定、情報不足 |

慢性傾向が低いことを、現在使用していない根拠にしない。0～1のスコアを残す場合も、検証前に実際の服薬確率として扱わない。

### 4.2 投与日数を正規化・推定する

優先順位案:

1. 元データに明示された日数。
2. 総数量と実際の用法からの計算。
3. 製品容量・総吸入回数等と用法からの計算。
4. 当該患者の過去の反復処方間隔による推定。
5. 推定不能なら不明。

Timesを一律に日数と解釈しない。SourceとMeTrIdCl等の意味、内服・外用・頓用の違いを元仕様と匿名化した実例で確認する。Qua1が1日量か総量かも区別する。

開始日には処方日・調剤日等のどれを使うかを定義し、日付の根拠を保存する。

### 4.3 吸入薬の個別対応

基本式:

    推定日数 = 個数 × 1個あたりの総吸入回数 / 1日の使用吸入回数

例として、レルベア14吸入用・30吸入用を1日1回1吸入で使用する条件なら、1個はそれぞれ14日分・30日分になる。

- 製品コードごとの容量・吸入回数と、その処方の用法を優先。
- 薬剤名の数字だけで機械的に判断しない。
- 標準用法で補う場合は推定であることを明示。
- 用法可変・頓用の場合は終了日を無理に確定しない。
- 頻出する吸入薬から小さなマスターを作り、対象を段階的に拡大。
- 同じ方法を貼付剤等へ拡張するかは別途検討。

### 4.4 推定終了日と情報の遅れを使う

    推定終了日 = 開始日 + 推定日数 - 1

この終了日を基準に、過去の処方間隔、早期再処方、残薬、記録の反映遅延を考慮する。重複期間の数量を無条件に積み増さない。用量変更時は単純な持ち越しを避ける。

以下を区別する。

- 処方上、まだ薬が残る。
- 次の処方が未反映の可能性がある。
- 十分新しい観測があるのに、その薬だけ長く途切れている。

レセプト由来等の情報遅延を、服薬中断と混同しない。ReceiveDateが新しいだけで、処方情報が現在まで完全に揃っているとは判断しない。中断疑いの猶予期間は固定値を即決せず、データ種別と実例で調整する。

### 4.5 継続履歴の統合

- 成分・投与経路等で継続性を評価し、製品・規格の変更に対応。
- 相互作用用には元の製品コード、規格、配合成分を保持。
- 配合剤、単剤への変更、異なる経路を安易に同一薬として統合しない。
- 訂正前レコードを除外し、処方・調剤等の重複を整理。
- 薬効分類は補助情報とし、NSAIDsを一律急性、吸入ステロイドを一律使用中としない。

### 4.6 相互作用用の候補とLLM要約用の候補を分離

相互作用候補には、使用期間内、継続可能性あり、頓用・不明の薬を保持する。確かさで表示優先度を変え、低スコアや15剤制限だけで候補から落とさない。

LLMには以下のような根拠付き情報を渡し、文章化を担当させる。

- 治療パターン、使用状態、確かさ。
- 最終処方日、推定日数、推定終了日。
- 推定方法と根拠、情報不足・反映遅延の可能性。
- 必要に応じて反復回数、代表処方間隔、元の用法。

共通の使用状態推定処理を作り、ペイロードと相互作用画面が別々の判定を持たないようにする。

## 5. 段階的な実施計画

### 第1段階: 入力整理と明らかな誤判定の修正

- [ ] 元XML仕様と実例でSource、Times、Qua1、MeTrIdCl、日付の意味を確認。
- [ ] Revised除外と処方・調剤の重複処理を確認。
- [ ] コードなし薬の抽出時集約を見直す。
- [ ] 保存済みテンプレートの「60日で中断」「30日以内なら臨時」を確認・改訂。
- [ ] 旧判定を再現できる比較用ケースを作成。

### 第2段階: 日数・終了日の推定

- [ ] 通常内服と長期処方に対応。
- [ ] 頻出吸入薬の容量マスターと用法解釈に対応。
- [ ] 頓用・用法不明は独立して扱う。
- [ ] 算出根拠、推定終了日、確かさを保持。

### 第3段階: 継続性・現在使用状態の分離

- [ ] 成分・経路に基づく履歴連結。
- [ ] 月カバレッジ中心から推定使用期間の連続性へ移行。
- [ ] データ反映遅延、観測不足、薬剤変更を区別。
- [ ] 判定根拠が分かる表示とペイロードを作成。

### 第4段階: 相互作用への接続と評価

- [ ] 要約用の薬剤数制限から独立した対象薬の抽出。
- [ ] 不確実な候補を除外せず、優先度や表示区分で扱う。
- [ ] 旧方式との比較結果を見て閾値等を調整。

## 6. 評価用ケースと指標

最低限用意するケース:

- 毎月の慢性内服、90日処方の途中。
- 開始したばかりの長期治療薬。
- 短期NSAIDsの処方直後と終了後。
- 頓用NSAIDs。
- 14吸入用・30吸入用、複数個処方、用法不明の吸入薬。
- 定期注射。
- 後発品・規格変更、配合剤と単剤の切り替え。
- 処方・調剤の重複、訂正前データ。
- 情報反映遅延、実際の中断、観測不足。
- 多剤併用、薬剤コード欠落。

評価指標:

- 使用中と確認された薬の見逃し率。
- 終了薬を使用中と推定する割合。
- 慢性・短期・頓用の分類精度。
- 中断疑いの誤検出。
- 不明と判定する割合、および推定根拠の妥当性。
- 相互作用候補の見逃しと不要な警告の両方。

基準日を固定できる純粋な判定処理にしてテストする。履歴の末尾を隠した過去時点の評価などを行う場合は、後日情報を当時の判定に混ぜない。

## 7. 再開時に決めること

- 実データでどの薬・どの処方パターンを優先するか。
- 推定に必要な投与日数・用法が、現在の保存項目でどこまで分かるか。
- 吸入薬マスターの取得元、管理方法、更新方法。
- 推定日数の幅、猶予期間、信頼度の表示方法。
- 既存のChronicScore / AcuteScoreとの互換性。
- 使用中・中止・頓用を手動確認する機能の要否。
- DB変更が必要か。まず既存項目から算出できる範囲を確認する。

## 結論

入口として効果が見込めるのは、保存済みの数量・用法等から推定終了日を出すことと、「最終処方から60日経過 = 中断」という指示を改めること。その上で、長期治療の傾向と現在の使用状態を分離し、根拠と不確実性を保持した共通判定へ発展させる。
