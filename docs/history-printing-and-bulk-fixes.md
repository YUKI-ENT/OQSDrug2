# 処方歴原文・健診印刷とBulkConsole修正

## 表示・印刷

薬歴フォームの「処方歴」の右隣に「処方歴原文」を追加した。SQL元データを日付・処方元等でまとめ、保存された薬剤行、一般名、用法、数量、日数／回数を表示する。見出しの順序は「日付 → 処方元 → 処方日 → 調剤薬局 → 情報源」。処方元名がない場合は診療施設名を使用し、別の調剤薬局がない場合は薬局の表示を省略する。

原文タブの画面では患者ID・氏名・期間・自施設除外条件、および受信PDF原本ではない旨の説明は表示しない。印刷時は患者名・ID・出力期間をタイトル直下に表示する。対象データは従来どおり選択患者・現在の期間・自施設除外条件に従う。

既存の処方歴ピボットは、上部ToolStripの印刷アイコンからA4横で印刷する。印刷アイコンは選択中の「処方歴」「処方歴原文」に応じて対象を切り替える。原文タブ内の印刷ボタンは置かない。表示中の列・行・値を使用し、画面上でスクロールしないと見えない列や行も対象になる。日付列は6列ずつ分け、各列グループで処方元・薬剤名・用法を繰り返す。月別表示や表示条件も画面の状態に従う。

健診フォームには新しいタブを設けず、既存の一覧とツールバーを維持する。上部ToolStripの印刷アイコンから従来の横並びの結果をA4縦で印刷する。実施日列は4列ずつ分け、項目名・単位を繰り返す。画面の非表示列は印字しない。

プレビュー内の「プリンターを選んで印刷」で出力先を選択する。Microsoft Print to PDF等も選択可能。プレビューは開いた時点の表示データを保持する。患者解除・読み込み開始時は印刷ボタンを無効化し、現在の患者の取得完了後に有効にする。

長い名称・結果は折り返し、1ページを超えるセルも継続して印字する。各ページに列見出しを繰り返す。横方向の分割はタイトルに列グループ番号、縦方向の分割はフッターにグループ内のページ番号を表示する。

## データの制約

原文タブはSQLに保存済みの履歴の再構成であり、受信PDFの複製ではない。処方箋IDがないため同日・同一施設等の同一キーの別処方を完全には分けられない。DBにない保険情報・健診判定基準などを補完しない。数量・Timesは一律に一日量・日数と解釈せず、取得値を表示する。

## BulkConsoleの手動選択・再送信

送信済み・重複扱いを手動選択の対象から除外していたため、選択しても送信ボタンが有効にならず、「全件チェック」でも対象にならなかった。

ユーザーの指定により、手動送信では送信済み・重複も選択して再送信できるようにした。チェックの変更を即時反映し、「全件チェック」「全件解除」とボタン状態を同期する。送信中の重複操作を防ぐ。別の資格情報インポート画面でも手動再送信を利用できる。

`QualificationFaceExporter.ExportAsync`に`allowResend`（既定false）を追加した。手動コールバックのみtrueを渡し、自動送信では従来の送信済み・重複スキップを維持する。成功した手動再送信は送信済みとして表示し、重複スキップの表示を解除する。同秒の再送信で既存ファイルを上書きしない。

## 同意XMLの修正

提供されたBulkTool出力と電カルオリジナル出力を比較したところ、保存値ではなく出力要素名に差異があった。

| 修正前 | 修正後 |
| --- | --- |
| PharmaceuticalInfoConsFlg / ConsTime | PharmacistsInfoConsFlg / ConsTime |
| PharmaceuticalInfoAcquisitionTime | PharmacistsInfoAvailableTime |
| SpecificHealthCheckupsInfoAcquisitionTime | SpecificHealthCheckupsInfoAvailableTime |
| DiagnosisInfoAcquisitionTime | DiagnosisInfoAvailableTime |
| OperationInfoAcquisitionTime | OperationInfoAvailableTime |

同意・拒否・期限は取得済みの値をそのまま使い、未取得の同意を生成しない。既存の出力ファイルは書き換えないため、修正後のアプリから必要なレコードを手動再送信する。

## 検証

`tests/Run-HistoryReportBulkTests.ps1`で、処方単位のグループ化・見出し順・行保持・日付順、ピボットの日付列分割と値の保持、健診の追加タブがないこと、複数ページ・長文の欠落防止、PrintDocumentのPreviewPrintControllerによる印刷経路、表示・患者解除時の印刷無効化、Bulkの単独選択と全件チェック、手動再送信と自動重複抑止、同意タグ・拒否値・未取得値を検証する。

架空データで画面と印刷ページを画像化し、表示を確認した。テスト出力はbin配下のhistory-report-testsに置く。実患者情報はテストフィクスチャへ保存しない。

実DB（PG/MDB）との接続、実プリンターでの印刷、修正XMLの電カル取り込みは実環境での確認が必要。テストは実プリンターへ印刷せず、電カル監視フォルダーにも送信しない。

## ツールバーのアイコン

印刷は既存のPrintリソースを使用する。薬効着色はDrugClassColors.png（32×32・透過PNG、4色の横バー）をリソースに登録し、画像のみのトグルボタンで表示する。どちらもツールチップで操作内容を確認できる。

## ピボット印刷のレイアウト調整

処方元はDGV同様、連続する同一施設を空欄とし、画面上の空欄を埋め直さない。薬歴印刷の幅は処方元16%、薬剤名25%、用法29%、日付列全体30%とする。折り返しの途中には横罫線を引かず、薬剤行の境界とページ端にだけ引く。日付見出しは画面の表記のまま1行で印字し、列幅に収まらない場合は見出しの文字サイズを調整する。FormDIの添付文書ボタンはDesignerのVisible指定をtrueにして表示する。

## 診療区分の出力停止

metridclには異なる情報源の区分が格納されているため、処方歴原文の画面・印刷では診療区分を出力しない。薬剤名／一般名／用法と数量・日数等の2列とする。区分データの取り込み・保存は変更しない。

## 印刷ヘッダーの患者・期間

処方歴・処方歴原文・健診の全ページに患者名、ID、出力期間を表示する。患者情報と期間はデータ取得完了時に保存し、プレビュー作成時にその内容を使う。期間は取得した印刷対象データの日付の最小～最大（処方歴はdidate、日付欠落時はmetrmonth、健診はeffectivetime）。月のみのデータは月表示とし、不明値はその旨を表示する。横方向の分割ページでも同じ全体期間を表示する。
