# 当日処方と他院薬の相互作用チェック（初版）

## 利用方法

1. 設定のダイナミクス読み取り方式をCOMにする。
2. Viewer設定に現れる「相互作用チェックを行う」をオンにして保存する。既定はオフ。
3. 薬歴フォームに「相互作用チェック」タブが追加される。メイン画面の同名ボタンからもこのタブを開ける。
4. タブ内の「再取得・チェック」で手動チェックできる。他院処方の対象は3か月または6か月（初期値6か月）。

PostgreSQLモードと、取り込み済みのdrug_code_map、drug_contraindication、sgml_rawdata、sgml_interactionを使用する。
MDBモードではチェック不能の理由を表示する。COM以外では設定項目を非表示にし、保存したオン・オフの値は維持する。
薬歴・健診・診療の自動表示がすべてオフでも、この設定がオンならCOM監視を開始する。

## 自動検知

- 患者番号の監視は500ms。薬剤取得は前回の処理完了から最低3秒空け、読み取りやチェックの重複実行はしない。
- 患者マスターの受診投薬サブフォームをRecordsetCloneで取得する。実フォームの保存・再クエリ・カーソル移動は行わない。
- 元の列名と、式1～式6の別名に対応する。
- 枝番付きカルテ番号、現在の受診コードを検証し、受診テーブルの受診日が今日の場合だけチェックする。
- 入力途中でDirtyの場合は待機する。エラーはフォーム内と間隔を空けたログで表示し、MessageBoxを連発しない。
- 「処方箋料」を含む行が現れ、同じ一覧を2回取得できたらチェックする。初回に開いた確定済み受診も同様。
- 確定行は一覧に表示するが薬剤照合から除外する。
- 確定済み処方のチェック完了後は結果を保持し、薬剤取得・自動チェックを停止する。患者番号（枝番を含む）の変更・フォーム閉鎖でリセットする。
- 同じ患者の再編集・再確定・別受診への切替は、タブの「再取得・チェック」を使用する。完了後は薬剤・受診の変更を監視しない。
- 他院薬歴が後から取り込まれた場合は結果を未チェック表示にし、手動再チェックを案内する。自動チェックは再開しない。
- 院内処方の確定行名・コードは未確認のため自動検知対象にしていない。手動チェックを利用する。

監視間隔に加えてCOMやDBの応答待ち時間がかかる。
チェック後に患者・受診・薬剤一覧を再取得し、変化していたら結果を破棄する。

## チェック内容

### KOROコード照合

ダイナの薬コードを薬マスターの厚生省コードへ変換する（薬コード0～99999、不使用<>2）。
KOROのT_厚生禁忌から取り込み済みのdrug_contraindicationを、レセ電コードの正逆両方向で照合する。
収録外の組み合わせ、コード欠落、先発・後発品の別コードを完全に解決するものではない。

### 文字列照合

drug_code_mapとsgml_rawdataからYJコード、販売名、一般名を補い、両薬剤の相互作用欄を確認する。
全半角・空白を正規化し、列挙・括弧区切りの名称（4文字以上）を相手の入力名・販売名・一般名に照合する。
薬効群の「阻害」「誘導」、除外表現、短い断片では直接一致させない。
薬効群のみの記載、未知の略称、複雑な除外・配合剤の表現は網羅しない。文字列結果は候補として原文と一緒に確認する。

### 他院薬

drug_historyから主番号、期間、prisorg<>1、revised IS NOT TRUEで取得する。
薬剤コードごとの最新記録を採用し、コード欠落時は名前を使用する。
最終処方日と医療機関を表示する。現在使用中かどうかの推定は行わない。
自施設不明（prisorgがNULL）の履歴は対象に含めない。

## 表示

- カルテ入力一覧、KOROコード照合、文字列照合の3タブ。
- 患者番号・枝番・氏名・受診コード・日付を表示する。
- コード未取得・YJ未対応の件数、参照データ件数を表示する。
- 薬歴タブのバッジは緑＝該当なし、赤＝要確認あり、灰＝未チェック・取得失敗。文字でも状態と検出件数を表示する。
- 自動チェック結果で別ウィンドウを開いたりフォーカスを移したりしない。変化のない一覧を再バインドせず、チェック完了後は表示を保持する。
- 薬歴で選択した患者とAccessの患者が一致しない場合、結果を表示しない。監視停止・患者変更時は古い結果を破棄する。
- エラーを「該当なし」と扱わず、未チェックとして表示する。

## 検証

tests/Run-DynamicsComSmokeTests.ps1でビルド、COM既存回帰テスト、確定安定検知、再編集・再確定、別受診・別枝番、列名別名、KORO正逆照合、一般名一致・短い断片除外、フォーム描画を確認する。

実機確認が必要な項目:

- 当日受診と過去受診を開いた際の動作。
- 実際のサブフォームの列名・受診コード・受診日の取得。
- 処方箋料の追加、再確定時の更新・置換。
- 院内処方の確定行名とコード。
- 実データのコード対応率、KOROと文字列の検出結果。
- 入力中、薬削除、患者切替、Access終了、設定解除中の挙動。

この初版では実際のダイナミクスと相互作用DBを組み合わせた動作確認は未実施。
