# res取込の独立実行

MakeReqは従来のタイマーで実行する。res取込は `ResImportWorker` が独立して実行し、MakeReqの周期を超えても実行中の走査を中断しない。

- 「開始」中は、ファイル通知がなくても5秒間隔で走査する。走査が長い場合は完了後に次の待機へ進み、走査同士は重複しない。
- ファイル通知を受けた場合は2秒待って走査する。処理中の通知は次回分として保持する。
- `ProcessResAsync` は毎回ファイル一覧と `resFile IS NULL` の要求行を読み直す。そのため、処理中に到着したXML、起動前から残っていたXML、通知を取りこぼしたXMLも再確認できる。
- DBロックで走査をスキップした場合や例外が起きた場合も、その後の周期で再試行する。
- RSBaseの自動表示やファイル監視の有無は、定期走査に影響しない。
- 「停止」中は新しい走査を開始しない。実行中の走査は完了まで進める。アプリ終了時にはワーカーを停止する。
- 従来のタイマー待機ループと、そこから呼んでいた「1日経過した未完了要求を削除する処理」を削除した。まだ取込対象になっている要求は、時間経過だけで失われない。

MakeReqの再要求条件、DBのスキーマ、XML解析・保存・SJIS変換の判定は今回変更していない。すでに `resFile` が記入されている行の再取込や、削除済み要求行の復元は行わない。

## 確認

`tests/Run-ResImportWorkerTests.ps1` で、実運用のDBやXMLにアクセスせずワーカーを検証する。

- 模擬応答20件の処理中に5件を追加し、通知なしでも25件すべてを処理。
- 長い取込を継続し、複数の走査を同時実行しない。
- 取込中の通知を次回走査へ引き継ぐ。
- DB待ち相当のスキップ、例外後に自動再試行。
- 停止状態からの再開と、実行中の走査完了後の終了。

実際の残存XMLについては、対応する要求行が残っていて `resFile IS NULL` であることを確認し、アプリを「開始」にすると再走査される。
