# ダイナミクスのCOM読み取り

「設定」→「取込設定」→「ダイナミクスの場所」で選択する。

- **mdbから読み取り**：従来の方式。datadyna.mdbまたはクライアントMDBを指定する。既存設定の既定値はこちら。
- **COM読み取り**：場所欄と参照ボタンを無効にする。既存のパスは保持するが、取得には使わない。

COM方式は起動中の `Access.Application` に接続し、開いているフォーム「患者マスター」とテーブル `WKO資格確認結果表示` の存在を確認する。クライアントファイル名は指定しない。複数Accessの選択UIは設けず、取得できたインスタンスを使用する。取得したAccessが条件を満たさない場合は接続待ちになる。

未起動・切断・一時的な呼出し拒否時は、通常のタイマーで再確認する。接続確認は取得開始前にも動作する。自動で取得を開始するかどうかは、既存の「自動開始/停止」設定に従う。Accessの新規起動やMDB直接読み取りへの自動フォールバックは行わない。

## 実装範囲

- `DynamicsComReader`：メッセージループ付き専用STAスレッドに読み取りを直列化する。各読み取りで起動中Accessを再取得するため、終了後のCOM参照を保持しない。
- 資格確認は `WKO資格確認結果表示` 固定。DAOの読み取り専用スナップショットから256行ずつ取得し、COM参照を含まない `DataTable` を返す。取得失敗時には部分データを返さない。
- 定期取得、MDBモードの資格確認一覧、一括取得結果の患者照合がCOM方式に対応する。PGモードの一覧は従来の保存済みデータを表示する。
- `DynamicsDataSource`：KORO読取元だけを切り替える。`TG医薬品マスター`、`T_MEDIS一般名`、`T_厚生禁忌`、`T_更新日` は同名リンクを使用する。
- PGのテーブル定義、COPY、変換、保存形式は維持する。MDB保存先では従来どおりコード対応辞書を読む。
- 起動時に読めなかったマスターは、Access接続後にタイマーから再試行する。失敗時のマスター再試行は最短1分間隔。COM取得失敗時には保存済みPGのコード対応辞書を利用できる。
- 資格確認のCOM読み取りに失敗した場合、古いキャッシュを新しい自動要求に使わない。
- Accessの `Quit` や現在のDBの `Close` は呼ばない。取得したスナップショットのみを閉じる。

COMサーバーからの一時的な呼出し拒否は1呼出しにつき最大1.5秒再試行する。これは処理中の全COM呼出しを強制中断するタイムアウトではない。Access自体やリンク先が応答しなくなった場合の待ち時間は実機で確認する必要がある。

## 検証

`tests/Run-DynamicsComSmokeTests.ps1` は署名を無効にしたDebug/x86ビルド後、独立したテストプログラムを実行する。メイン画面は起動せず、ユーザー設定を保存しない。

- 模擬DAOによる600件の分割取得、文字列コードの先頭ゼロ、NULL、金額、日時、真偽値。
- 0件時の列情報維持、フォーム／テーブル欠落、取得途中の失敗とスナップショットの解放。
- 設定切り替え、パス欄と参照ボタンの有効／無効、既存パスの保持。両モードのPNGをテスト出力先へ生成。
- Accessが起動していない環境では、STA接続確認の反復と、MDBへのフォールバックやAccessの新規起動がないことを確認。

実機では次を確認する。

1. OQSDrugを先に起動し、後から電カルを起動すると接続可能になる。
2. 電カル終了・再起動後に再接続する。取得再開は自動開始設定に従う。
3. WKOの列・件数・同意情報、およびKOROの4リンクと更新日が期待どおりである。
4. 電カル操作中・ダイアログ表示中・リンク先切断時の待機と復旧。
5. マスター取得中の電カル操作への影響、メモリ使用量、所要時間。
6. MDB方式へ戻すと保存済みパスで従来どおり取得できる。
